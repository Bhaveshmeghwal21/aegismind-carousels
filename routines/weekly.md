# Weekly ideas routine

You plan next week's posts for the Instagram account @theaegismind: single-image posts in a black-and-white manga ink style: a white page with the quote in a heavy serif at the top, the thinker and the work under it, and an original ink illustration below. Each post is a quote by a real thinker (philosophers, sages, warriors, mystics). The owner reads your file and fills any gaps by editing it on GitHub, so write it to be edited. You are working in a clone of this repo on `main`. You start with no memory, so follow these steps in order.

Hard rules:
- Never edit or delete an existing file in `ideas/`. You only add one new file.
- Never invent or "improve" a quote, and never attribute a line to someone who is not known to have said it. Misattributed quotes are everywhere online, so do not trust a quote just because it is popular. When you are not sure of the exact wording or the author, mark the entry `needs-check` (see below).

## Steps

1. `git pull --ff-only origin main`, then `python3 -m pip install -q -r requirements.txt`.
2. Work out next week: the coming Monday in India (`TZ=Asia/Calcutta date`), and its ISO week label `YYYY-Www` (for example `2026-W49`). If `ideas/<label>.md` already exists, stop and report; do not overwrite it.
3. Read `ideas/2026-W48.md` as the exact format to copy. Then read every other file in `ideas/` and note which authors, quotes and images have been used. Read `assets/art/index.json`: it lists the pictures you can choose from. Only the entries with `"kind": "ink"` are used now; the older museum photos are not. Work out which ink ids have never been used in any `ideas/` file: only those are available.
4. Write `ideas/<label>.md`. Its very first line is `approved: no`, then a blank line. The owner changes it to `approved: yes` after reviewing the week; until then nothing in the file is posted. Never write `approved: yes` yourself. Then write exactly 7 entries, one for each day Monday to Sunday, headed `## YYYY-MM-DD`. Each entry has these lines: `status`, `quote`, `author`, `source`, `image`, `music`, `caption`, `tags` (and `note` only when needed).
   - Thinkers: you choose, and there is no fixed list. Search the web for strong quotes and pick from any philosopher, sage, mystic, warrior, writer or psychologist of any era and culture (Greek and Roman, Indian, Chinese, Japanese, Persian, Arab, African, medieval, modern, existentialist, and so on). Lesser-known voices are welcome. Do not use an author who appears in the last 6 weeks of files in `ideas/`, never repeat a quote, and keep the week varied: no author twice, and no more than two entries from the same tradition.
   - `quote`: the words exactly as written in a named work, without quotation marks. Short: at most 140 characters, so it fits the image. Prefer public-domain translations (for example George Long for Marcus Aurelius, Richard Gummere for Seneca, F. Max Müller for the Dhammapada, Benjamin Jowett for Plato, James Legge for Chinese classics) so the wording can be quoted freely. Use web search to find where in the work the quote sits, and confirm the wording against the text of the work (Project Gutenberg, Perseus, Wikisource, a publisher), not against a quote website. If you cannot reach any source, use only a quote you are certain of and otherwise mark the entry `needs-check`.
   - `author`: the name as people know it, for example `Marcus Aurelius`.
   - `source`: the work, the section and the translator, for example `Meditations 5.16, tr. George Long`. Every entry needs one.
   - `image`: one id of a `"kind": "ink"` entry in `assets/art/index.json` that suits the quote's mood and the thinker (`ink-samurai` for a warrior's words, `ink-emperor` for a Roman or a ruler, `ink-monk` for Buddhist or inward words, `ink-thinker` for a Greek or a question, `ink-cliff` for courage, solitude or a journey, `ink-writer` for letters, writing or a lone thinker, `ink-freedman` for freedom, hardship or hope). NEVER reuse a picture: every post gets an image that no entry in any file in `ideas/` (this week or any earlier week) has used. Collect the used ids first, then choose only from the `"kind": "ink"` ids not on that list, and no id twice in the same week. If no unused ink id remains for an entry, do not reuse one and do not leave `image:` empty: write `status: needs-check` and `note: needs new ink art`, so the entry cannot post, and tell the owner in your final report how many entries are waiting for new art. The art is a mood, not a portrait of the thinker; never write a caption that claims otherwise.
   - `music`: one id from `assets/music/index.json` (each has a `mood` note). Pick the piece whose mood suits the quote, for a serious and quietly dramatic feel. No track twice in the same week, and avoid the tracks used in the previous week's file.
   - `caption`: one or two short sentences of reflection, or a question for the reader. A fact (a date, a place) only if you are sure of it. No hashtags here.
   - `tags`: three to five hashtags on one line.
   - If you are not sure of a quote's exact wording, the translation, or who said it, set `status: needs-check` and add a `note:` line saying what to check. Entries marked `needs-check` are never posted.
   - Use plain letters, digits, ordinary punctuation, curly quotes and em dashes. Accented Latin letters (for example ō, é) are fine. No emoji, no Greek, Chinese or other non-Latin letters.
5. Check it renders: for each of the 7 dates run `PYTHONPATH=src python3 -m carousel render --date DATE --out /tmp/check --reel 3`. Because the week says `approved: no`, the command stops with exit 3 and "week not approved". To test the entries, copy the file to a temporary place, change that line to `approved: yes` in the copy only, and run the check against the copy (`--ideas <temporary folder>`). Exit 0 is good. Exit 3 is expected only for `needs-check` entries. An unsupported-character, text-too-long, unknown-image or unknown-music error means you fix that entry and run it again.
6. `git add ideas/<label>.md && git commit -m "ideas: week <label>" && git push origin main`.
7. Send a push notification (PushNotification) saying that week `<label>` is written and waits for the owner's approval: open `ideas/<label>.md` on GitHub, review it, and change `approved: no` to `approved: yes`.
8. Report: the 7 dates with author and the first words of each quote, any `needs-check` entries and what to verify, and a reminder that nothing is posted until the owner approves.
